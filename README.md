Лабораторная работа №6: Подключение бэкенда и мультимодальный поиск CLIP
Цель работы
Подключение разработанного ранее веб-сервиса (Django REST) к React-приложению, реализация трёх GET-запросов (список услуг с фильтрацией, детали услуги, иконка корзины) и внедрение мультимодального поиска с помощью модели SigLIP (CLIP) для поиска услуг по загруженному изображению.

Реализованные возможности
Три страницы: список услуг, детали услуги, корзина (заявка).

Работа с бэкендом: данные загружаются через fetch с проксированием для обхода CORS.

Фильтрация услуг по названию и дате (параметры передаются в запрос к бэкенду).

Fallback на mock-данные при недоступности бэкенда (приложение не падает).

Хранение изображений и видео в объектном хранилище MinIO.

CLIP-поиск (SigLIP) – загрузка изображения, вычисление эмбеддингов, косинусное сходство с английскими описаниями услуг, фильтрация по порогу (0.004) и ограничение количества результатов (TopK=6).

Навигация (Navbar) и хлебные крошки (Breadcrumbs) – реализованы вручную без Redux/Context.

Запуск приложения
Требования
Node.js (v18+)

Docker (для MinIO, PostgreSQL, Redis – опционально)

Запущенный бэкенд на Django (порт 8000) с настроенными эндпоинтами:

/api/bank_services/ (список услуг, поддержка фильтров name, start_date, end_date)

/api/bank_services/{id}/ (одна услуга)

/api/bank_requests/cart/ (иконка корзины – может возвращать 401 без авторизации, но запрос выполняется)

MinIO с bucket bank, папками img/ и video/, публичным доступом.

Установка и запуск
bash
# 1. Установить зависимости
npm install

# 2. Запустить фронтенд (по умолчанию порт 3000)
npm run dev
Приложение автоматически проксирует запросы /api на http://localhost:8000 (настройка в vite.config.ts). Если бэкенд не запущен, срабатывает fallback на mockServices.ts.

Демонстрация (порядок показа)
Три страницы с mock-данными – остановить бэкенд, обновить страницу – данные из mockServices.ts.

Три страницы с бэкендом – запустить Django, в Network видно проксирование (/api/bank_services/).

Прокси и CORS – показать Request URL = http://localhost:3000/api/..., объяснить vite.config.ts.

MinIO – показать запросы к http://localhost:9002/bank/img/... и код формирования URL в ServiceCard.tsx.

Изменение БД – добавить услугу через админку Django, обновить фронтенд – новая карточка появляется.

Fetch-запросы – открыть api.ts, объяснить fetch, async/await, URLSearchParams, fallback.

Три GET-запроса – найти в Network: список услуг (с ?name=кредит), одну услугу (/bank_services/1/), иконку корзины (/bank_requests/cart/).

CLIP-поиск – дождаться загрузки модели (прогресс 100%), загрузить фото, увидеть изменение списка. Показать в коде порог (threshold = 0.004) и TopK (TOP_K = 6).

Контрольные вопросы (краткие ответы)
CORS и обратный прокси
CORS – политика безопасности браузера, запрещающая запросы к другому источнику (порту, домену).

Обратный прокси – в vite.config.ts запросы с /api перенаправляются на http://localhost:8000. Браузер видит тот же источник (3000), CORS не возникает.

BFF и GraphQL
BFF (Backend for Frontend) – промежуточный слой, который агрегирует данные из микросервисов для конкретного фронтенда.

GraphQL – язык запросов, позволяющий клиенту запрашивать только нужные поля. Может быть реализацией BFF.

Next.js и SSG
Next.js – React-фреймворк с поддержкой серверного рендеринга (SSR) и статической генерации.

SSG (Static Site Generation) – страницы генерируются на этапе сборки, что даёт высокую скорость и SEO.

FSD (Feature‑Sliced Design)
Методология организации кода, делящая проект на слои: shared, entities, features, widgets, pages, app. Каждый слой может использовать только нижележащие, что обеспечивает изолированность и переиспользование.

Примечания
Порог CLIP: выбран 0.004 из‑за особенностей модели SigLIP (задание рекомендует 0.4–0.9 для классического CLIP, но для SigLIP это значение слишком высокое и не даёт результатов). Код позволяет легко изменить порог.

TopK: 6 – максимальное количество отображаемых результатов поиска.

Фильтр по дате: для полноценной работы требуется поле created_at в модели BankService бэкенда; в текущей реализации фильтр работает на мок-данных, а с бэкендом – после добавления поля.

Иконка корзины: может возвращать 401 (требуется авторизация), но фронтенд обрабатывает ошибку и показывает счётчик 0.
